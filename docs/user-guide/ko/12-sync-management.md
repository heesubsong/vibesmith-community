# 동기화 관리

> 📝 이 문서는 자동으로 생성되었습니다. 내용이 부정확하거나 누락된 부분이 있다면 [Issue](https://github.com/heesubsong/vibesmith-community/issues)로 제보해주세요.

## 동기화란?

**동기화(Sync)**는 로컬과 글로벌 컴포넌트를 자동으로 일치시키는 기능입니다. 프로젝트별 컴포넌트와 전역 컴포넌트를 효율적으로 관리할 수 있습니다.

### 왜 동기화가 필요한가?

**문제 상황**:
```
프로젝트 A: skill-x (v1.0) ← 수정함
프로젝트 B: skill-x (v0.9) ← 옛날 버전!
프로젝트 C: skill-x 없음  ← 아직 추가 안 함!
```

**동기화 후**:
```
프로젝트 A: skill-x (v1.0) ✅
프로젝트 B: skill-x (v1.0) ✅ 자동 업데이트
프로젝트 C: skill-x (v1.0) ✅ 자동 추가
```

## 동기화 설정

![동기화 설정](images/sync-01-settings.png)

**Settings** > **Sync**에서 동기화를 관리할 수 있습니다.

## 로컬 vs 글로벌

### 로컬 컴포넌트
**위치**: `.cursor/`, `.claude/`

**특징**:
- 현재 프로젝트에만 적용
- 프로젝트 특화 로직
- 빠른 실험 및 테스트

**예시**:
```
.cursor/skills/
├── project-specific-skill/
├── custom-workflow/
└── temp-experiment/
```

### 글로벌 컴포넌트
**위치**: `~/.cursor/`, `~/.claude/`

**특징**:
- 모든 프로젝트에 적용
- 범용적인 스킬
- 재사용 가능한 패턴

**예시**:
```
~/.cursor/skills/
├── react-component-generator/
├── code-formatter/
└── test-writer/
```

### 언제 어떤 것을 사용할까?

#### 로컬로 유지
```
✅ 프로젝트별 코딩 규칙
✅ 특정 도메인 로직
✅ 실험 중인 스킬
✅ 비밀 정보 포함

예: "customer-api-wrapper" → 이 프로젝트만
```

#### 글로벌로 승격
```
✅ 여러 프로젝트에서 사용
✅ 검증된 패턴
✅ 팀 전체 공유
✅ 범용적인 기능

예: "react-component-generator" → 모든 프로젝트
```

## 동기화 방향

### 1. 로컬 → 글로벌 (승격)
**사용 시기**: 유용한 스킬을 다른 프로젝트에도 사용하고 싶을 때

**예시**:
```
로컬에서 개발 → 테스트 → 검증 완료 → 글로벌로 승격
```

**방법**:
1. 스킬 상세 페이지 열기
2. **글로벌로 승격** 버튼 클릭
3. 확인

### 2. 글로벌 → 로컬 (복사)
**사용 시기**: 글로벌 스킬을 프로젝트에 맞게 커스터마이즈

**예시**:
```
글로벌 스킬 복사 → 로컬에서 수정 → 프로젝트 특화
```

**방법**:
1. 글로벌 스킬 선택
2. **로컬로 복사** 버튼 클릭
3. 필요시 수정

### 3. 양방향 (자동)
**사용 시기**: 최신 버전을 자동으로 유지

**동작**:
- 로컬 수정 → 글로벌에 자동 반영
- 글로벌 수정 → 로컬에 자동 반영
- 충돌 시 사용자에게 알림

## 수동 동기화

![수동 동기화](images/sync-02-manual.png)

![수동 동기화 데모](gifs/sync-demo.gif)

**Sync** 버튼을 클릭하여 수동으로 동기화할 수 있습니다.

### 동기화 프로세스

#### 1단계: 변경 감지
```
🔍 로컬과 글로벌 비교 중...
  - 새로 추가된 파일: 3개
  - 수정된 파일: 2개
  - 삭제된 파일: 1개
```

#### 2단계: 충돌 확인
```
⚠️  충돌 발견:
  - skill-x: 로컬과 글로벌 모두 수정됨
  - skill-y: 로컬은 삭제, 글로벌은 수정됨
```

#### 3단계: 미리보기
```
📋 동기화 예정:
  ✅ skill-a: 로컬 → 글로벌
  ✅ skill-b: 글로벌 → 로컬
  ⚠️  skill-x: 충돌 해결 필요
```

#### 4단계: 실행
```
🔄 동기화 중...
  ✅ skill-a 업데이트
  ✅ skill-b 업데이트
  ⏭️  skill-x 스킵 (충돌)

✅ 완료! 2개 동기화, 1개 스킵
```

## 동기화 옵션

### 충돌 처리
- **덮어쓰기**: 기존 파일 교체
- **병합**: 내용 합치기
- **건너뛰기**: 충돌 항목 무시
- **백업 후 덮어쓰기**: 안전한 선택 ✅

### 범위 설정
- **전체**: 모든 컴포넌트
- **타입별**: Skills만, Agents만 등
- **선택**: 직접 선택한 항목만

### 백업
- **자동 백업**: 동기화 전 자동 백업
- **백업 보관**: 최근 10개 유지
- **복구**: 언제든 이전 버전으로 복구

## 충돌 해결

![충돌 해결](images/sync-03-conflicts.png)

충돌이 발견되면 **충돌 해결** 창이 나타납니다.

### 충돌 유형

#### 1. 이름 충돌
**상황**: 로컬과 글로벌에 같은 이름의 다른 컴포넌트

**해결**:
```
옵션 A: 하나를 이름 변경
  local-skill-x, global-skill-x

옵션 B: 우선순위 설정
  로컬 우선 → 로컬 것만 유지
  글로벌 우선 → 글로벌 것만 유지
```

#### 2. 내용 충돌
**상황**: 같은 컴포넌트를 로컬과 글로벌 모두 수정

**해결**:
```
옵션 A: 로컬 우선
  ← 로컬 변경사항 유지

옵션 B: 글로벌 우선
  → 글로벌 변경사항 유지

옵션 C: 수동 병합
  ↔ 둘 다 필요한 부분만 선택
```

#### 3. 의존성 충돌
**상황**: 의존성 체인에 순환 참조

**해결**:
```
Before: A → B → C → A (❌ 순환)
After:  A → B → C (✅ 정상)

방법: 의존성 재구조화
```

### 충돌 해결 전략

#### 안전한 전략 (권장)
```
1. 백업 생성
2. 충돌 항목 리뷰
3. 중요도 판단
4. 하나씩 해결
5. 테스트
```

#### 빠른 전략
```
1. 로컬 우선으로 일괄 적용
2. 나중에 필요하면 글로벌에서 가져오기
```

## 자동 동기화

![자동 동기화](images/sync-04-auto.png)

**Settings** > **Sync** > **Auto Sync**를 켜면 파일 변경 시 자동 동기화됩니다.

### 자동 동기화 동작

#### 파일 감시
```
🔍 파일 시스템 모니터링
  - 로컬: .cursor/, .claude/
  - 글로벌: ~/.cursor/, ~/.claude/
  
감지 대상:
  - 파일 생성
  - 파일 수정
  - 파일 삭제
  - 이름 변경
```

#### 변경 감지 시
```
1. 변경 사항 감지
2. 영향 범위 파악
3. 충돌 확인
4. 자동 동기화 or 알림
```

#### 충돌 알림
```
💬 알림:
   "skill-x에 충돌이 발견되었습니다.
    수동으로 해결해주세요."

[해결하기] [나중에] [무시]
```

### 동기화 규칙

#### 로컬 우선 규칙
**설정**: 로컬 변경사항을 글로벌에 자동 반영

**동작**:
```
로컬 수정 → 자동으로 글로벌 업데이트
글로벌 수정 → 알림만 (수동 승인 필요)
```

**사용 시기**: 개발 중인 프로젝트

#### 글로벌 우선 규칙
**설정**: 글로벌 변경사항을 로컬에 자동 반영

**동작**:
```
글로벌 수정 → 자동으로 로컬 업데이트
로컬 수정 → 알림만 (수동 승인 필요)
```

**사용 시기**: 안정적인 프로젝트

#### 양방향 규칙
**설정**: 최신 변경사항으로 자동 업데이트

**동작**:
```
로컬 수정 → 글로벌 업데이트
글로벌 수정 → 로컬 업데이트
동시 수정 → 충돌 알림
```

**사용 시기**: 팀 협업

#### 수동 확인 규칙
**설정**: 모든 변경사항을 수동 승인

**동작**:
```
모든 변경 → 알림 + 승인 대기
```

**사용 시기**: 중요한 프로젝트

## 동기화 간격

- **즉시**: 파일 변경 즉시 (비권장)
- **5분**: 5분마다 (기본)
- **10분**: 10분마다
- **30분**: 30분마다
- **수동**: 자동 동기화 끄기

### 간격 선택 가이드

```
✅ 5분: 활발한 개발 중
✅ 10분: 일반적인 작업
✅ 30분: 안정적인 프로젝트
✅ 수동: 네트워크 드라이브 or 대용량
```

## 베스트 프랙티스

### 1. 백업 활성화
```
✅ 항상 자동 백업 켜기
✅ 백업 보관 기간: 30일
✅ 중요한 변경 전 수동 백업
```

### 2. 충돌 예방
```
✅ 작업 전 동기화
✅ 작업 후 동기화
✅ 명확한 네이밍
✅ 의존성 최소화
```

### 3. 점진적 동기화
```
Step 1: 로컬에서 개발 & 테스트
Step 2: 검증 완료 후 글로벌 승격
Step 3: 다른 프로젝트에서 사용
```

### 4. 정기적 정리
```
월 1회: 사용하지 않는 컴포넌트 제거
분기 1회: 의존성 최적화
반기 1회: 전체 구조 리뷰
```

### ⚠️ 주의사항

⚠️ 자동 동기화는 의도하지 않은 덮어쓰기를 일으킬 수 있습니다.
⚠️ 중요한 변경 전에는 반드시 백업하세요.
⚠️ 네트워크 드라이브에서는 자동 동기화가 느릴 수 있습니다.
⚠️ 충돌을 무시하면 데이터 손실이 발생할 수 있습니다.
