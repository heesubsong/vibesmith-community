# 자주 묻는 질문 (FAQ)

> 📝 이 문서는 자동으로 생성되었습니다. 내용이 부정확하거나 누락된 부분이 있다면 [Issue](https://github.com/heesubsong/vibesmith-community/issues)로 제보해주세요.

## 일반 질문

### VibeSmith는 무료인가요?

네, VibeSmith는 개인 및 상업적 용도로 무료로 사용할 수 있습니다.

### VibeSmith를 상업적으로 사용해도 되나요?

네, 완전히 자유롭게 사용할 수 있습니다. 라이선스 비용, 사용자 제한, 프로젝트 제한 등이 전혀 없습니다.

### VibeSmith가 지원하는 AI 도구는 무엇인가요?

현재 지원하는 AI 도구:
- **Cursor** (VS Code 기반 IDE)
- **Claude Code** (Anthropic의 AI 에디터)

앞으로 GitHub Copilot, Codeium 등 더 많은 도구를 지원할 예정입니다.

### Cursor와 Claude Code의 차이는 무엇인가요?

| 비교 | Cursor | Claude Code |
|------|--------|-------------|
| **기반** | VS Code | 독립 에디터 |
| **AI 모델** | GPT-4, Claude | Claude 전용 |
| **가격** | 유료 ($20/월) | 무료 (Claude Pro) |
| **사용성** | IDE 친화적 | AI 대화 중심 |

VibeSmith는 두 도구 모두 완벽하게 지원합니다.

### VibeSmith의 주요 기능은 무엇인가요?

- **스킬 관리**: AI 에이전트의 재사용 가능한 명령어
- **에이전트 관리**: 복잡한 워크플로우 자동화
- **명령어 관리**: 슬래시 명령어로 빠른 실행
- **훅 관리**: Git 작업 자동화
- **규칙 관리**: 팀 코딩 컨벤션 적용
- **의존성 그래프**: 컴포넌트 간 관계 시각화
- **고급 검색**: 퍼지 검색, 정규식, 필터 검색
- **동기화**: 로컬 ↔ 글로벌 컴포넌트 동기화

### VibeSmith를 사용하려면 Cursor/Claude Code를 반드시 설치해야 하나요?

네, VibeSmith는 Cursor나 Claude Code의 설정 파일을 관리하는 도구입니다. 
AI 도구가 먼저 설치되어 있어야 합니다.

## 데이터 및 보안

### 데이터는 어디에 저장되나요?

모든 데이터는 **로컬 컴퓨터**에만 저장됩니다:

```
~/.vibesmith/               # VibeSmith 데이터
├── db.sqlite              # 프로젝트 인덱스 데이터베이스
├── config.json            # 앱 설정
├── backups/               # 자동 백업 파일
└── logs/                  # 앱 로그

.cursor/                   # 프로젝트별 컴포넌트
├── skills/
├── agents/
├── commands/
├── hooks/
└── rules/

~/.cursor/                 # 글로벌 컴포넌트
├── skills/
├── agents/
└── ...
```

**중요**: 외부 서버로 전송되는 데이터는 **전혀 없습니다**.

### 내 코드가 외부로 전송되나요?

아니요! VibeSmith는 **완전히 로컬**에서 작동합니다. 
- 네트워크 연결 불필요
- 클라우드 서버 없음
- 개인정보 수집 없음

### VibeSmith를 회사에서 사용해도 되나요?

네, 완전히 안전합니다:
- 모든 데이터는 로컬에만 저장
- 외부 네트워크 통신 없음
- 보안 정책 준수 용이

### 백업은 어떻게 하나요?

#### 자동 백업 (권장)
```
설정 > 일반 > 자동 백업
- 백업 주기: 매일 (기본값)
- 백업 위치: ~/.vibesmith/backups/
- 보관 기간: 30일
```

#### 수동 백업
```bash
# 1. VibeSmith 데이터 백업
tar -czf vibesmith-backup.tar.gz ~/.vibesmith

# 2. 프로젝트 스킬 백업 (Git 권장)
git add .cursor/
git commit -m "backup: save cursor components"

# 3. 글로벌 스킬 백업
cp -r ~/.cursor/skills ~/cursor-skills-backup
```

#### 복원 방법
```bash
# VibeSmith 데이터 복원
tar -xzf vibesmith-backup.tar.gz -C ~/

# Git에서 복원
git checkout HEAD -- .cursor/
```

## 프로젝트 관리

### 프로젝트별 vs 글로벌 컴포넌트의 차이는?

| 구분 | 로컬 (프로젝트별) | 글로벌 |
|------|------------------|--------|
| **경로** | `.cursor/skills/` | `~/.cursor/skills/` |
| **범위** | 현재 프로젝트만 | 모든 프로젝트 |
| **용도** | 프로젝트 특화 스킬 | 범용 스킬 |
| **Git** | 포함 권장 | 포함 안 함 |
| **우선순위** | 높음 (덮어쓰기) | 낮음 |

**사용 예시**:
- **로컬**: React 프로젝트 전용 컴포넌트 생성 스킬
- **글로벌**: 커밋 메시지 생성, 코드 리뷰 스킬

### 여러 프로젝트를 동시에 관리할 수 있나요?

네, VibeSmith는 멀티 프로젝트를 지원합니다:
- 여러 프로젝트 창 동시 열기 가능
- 각 프로젝트는 독립적으로 관리
- 글로벌 컴포넌트는 모든 프로젝트에서 공유

**팁**: 
```
파일 > 새 창 (Cmd+Shift+N)
→ 다른 프로젝트 열기
```

### 프로젝트를 추가하려면 어떻게 하나요?

**방법 1: 직접 열기**
```
파일 > 프로젝트 열기 (Cmd+O)
→ 프로젝트 루트 디렉토리 선택
```

**방법 2: 드래그 앤 드롭**
```
프로젝트 폴더를 VibeSmith 창에 드래그
```

**방법 3: 최근 프로젝트**
```
파일 > 최근 프로젝트
→ 목록에서 선택
```

### 프로젝트를 제거하려면?

```
프로젝트 리스트에서 우클릭 > 제거
```

**주의**: 
- 리스트에서만 제거 (파일은 삭제 안 됨)
- 실제 파일을 삭제하려면 Finder/Explorer 사용

## 스킬, 에이전트, 명령어

### 스킬과 에이전트의 차이는 무엇인가요?

| 구분 | 스킬 | 에이전트 |
|------|------|----------|
| **호출** | `@skill-name` | `@agent-name` |
| **복잡도** | 간단 (1-5 단계) | 복잡 (다단계 워크플로우) |
| **실행 시간** | 즉시 (초 단위) | 길게 (분 단위) |
| **출력** | 코드, 텍스트 | 보고서, 이슈, PR |
| **예시** | 컴포넌트 생성 | 스펙 → 구현 → 테스트 → PR |

**언제 스킬을 사용하나요?**
- 코드 스니펫 생성
- 파일 포맷팅
- 간단한 변환

**언제 에이전트를 사용하나요?**
- 기능 전체 구현
- 자동화된 워크플로우
- 여러 단계가 필요한 작업

### 명령어는 어떻게 다르나요?

**명령어(Commands)**는 슬래시(`/`)로 시작하는 빠른 액션입니다.

```
/spec-create 로그인 페이지
/auto-implement login-spec.md
/daily-log
```

**차이점**:
- 스킬: `@`로 호출, AI 컨텍스트에서 사용
- 명령어: `/`로 호출, 즉시 실행
- 에이전트: 장기 실행, 백그라운드

### 스킬을 어떻게 공유하나요?

#### 방법 1: Git으로 팀 공유 (권장)
```bash
# .cursor를 Git에 포함
git add .cursor/skills/
git commit -m "feat: add component generation skill"
git push

# 팀원이 pull하면 자동으로 사용 가능
```

#### 방법 2: 파일 복사
```bash
# 다른 프로젝트로 복사
cp -r .cursor/skills/my-skill /other/project/.cursor/skills/

# 글로벌로 이동 (모든 프로젝트에서 사용)
cp -r .cursor/skills/my-skill ~/.cursor/skills/
```

#### 방법 3: 커뮤니티 공유
```markdown
1. GitHub Gist에 업로드
2. README에 설치 방법 작성
3. 커뮤니티에 공유
```

### 에이전트가 너무 느려요

**원인**:
- 복잡한 워크플로우
- 대규모 프로젝트
- AI 모델 응답 시간

**해결 방법**:
1. **로그 확인**: 어느 단계가 느린지 파악
2. **단계 최적화**: 불필요한 단계 제거
3. **범위 축소**: 전체 스캔 대신 특정 디렉토리만
4. **더 빠른 모델 사용**: GPT-4 → GPT-3.5

### 규칙이 적용되지 않아요

**체크리스트**:
- [ ] 규칙이 활성화되어 있나요?
- [ ] 파일 패턴(globs)이 올바른가요?
- [ ] 우선순위가 더 높은 규칙이 있나요?
- [ ] 로컬 규칙이 글로벌 규칙을 덮어쓰고 있나요?

**디버그 방법**:
```
1. AI에게 직접 물어보기:
   "어떤 규칙이 현재 적용되어 있어?"

2. 규칙 로그 확인:
   설정 > 고급 > 규칙 적용 로그

3. 테스트:
   간단한 코드 생성 요청 후 규칙 적용 여부 확인
```

## 검색 및 필터링

### 검색이 느려요

**원인**:
- 대규모 프로젝트
- 인덱스가 오래됨
- 너무 광범위한 검색

**해결 방법**:
```
1. 인덱스 재구축:
   설정 > 고급 > 인덱스 재구축

2. 제외 경로 추가:
   설정 > 스캔 > 제외 경로
   - node_modules
   - .git
   - dist
   - build

3. 검색 범위 축소:
   - 특정 타입만 검색 (type:skill)
   - 특정 경로만 검색 (path:src/)
```

### 퍼지 검색이란?

**퍼지 검색(Fuzzy Search)**은 오타를 허용하는 스마트 검색입니다.

**예시**:
```
입력: "usrprofil"
결과:
- ✅ user-profile
- ✅ UserProfile
- ✅ user_profile_component
```

**활용**:
- 정확한 이름을 모를 때
- 오타가 있을 때
- 비슷한 이름 찾을 때

### 정규식 검색은 어떻게 사용하나요?

**정규식(Regex) 검색**으로 복잡한 패턴을 찾을 수 있습니다.

**활성화**:
```
검색창 > 옵션 > Regex (.*) 아이콘 클릭
```

**예시**:
```regex
# use로 시작하는 모든 훅
^use[A-Z].*

# 날짜 형식 (YYYY-MM-DD)
\d{4}-\d{2}-\d{2}

# API 엔드포인트
\/api\/v\d+\/.*

# 특정 태그 조합
tag:(api|hook).*tag:react
```

### 저장된 검색은 어떻게 사용하나요?

**저장**:
```
1. 검색 입력
2. 별표(⭐) 아이콘 클릭
3. 이름 입력 후 저장
```

**불러오기**:
```
검색창 > 북마크 아이콘 > 목록에서 선택
```

**관리**:
```
설정 > 검색 > 저장된 검색 관리
- 편집
- 삭제
- 순서 변경
```

**활용 예시**:
```
- "내가 만든 스킬": author:me type:skill
- "최근 1주일": modified:7d
- "테스트 관련": tag:test OR tag:testing
- "React 컴포넌트": type:skill tag:react path:components/
```

## 의존성 그래프

### 의존성 그래프는 어떻게 해석하나요?

**노드 (Node)**:
- **원**: 각 컴포넌트
- **크기**: 의존성 개수 (큰 원 = 많은 의존성)
- **색상**: 컴포넌트 타입
  - 🔵 파랑: Skill
  - 🟢 초록: Agent
  - 🟡 노랑: Command
  - 🔴 빨강: Hook
  - 🟣 보라: Rule

**간선 (Edge)**:
- **화살표**: 의존 방향
- **굵기**: 의존 강도 (많이 사용될수록 굵음)
- **색상**: 의존 타입

**예시**:
```
A → B: A가 B를 사용함
A ↔ B: 순환 의존 (주의!)
```

### 순환 의존성을 찾으려면?

```
의존성 그래프 > 필터 > 순환 의존만 표시
```

**해결 방법**:
1. 순환 경로 확인
2. 중간 컴포넌트 제거 또는
3. 의존 방향 역전

### 그래프가 복잡해서 보기 어려워요

**단순화 방법**:
```
1. 필터 사용:
   - 특정 타입만 표시
   - 특정 컴포넌트 중심으로

2. 레이아웃 변경:
   - 계층형 (Hierarchical)
   - 원형 (Circular)
   - 포스 기반 (Force-directed)

3. 깊이 제한:
   - 1단계만 표시
   - 직접 의존만 표시
```

### 그래프를 이미지로 저장하려면?

```
의존성 그래프 > 우클릭 > 이미지로 내보내기
- PNG (고품질)
- SVG (벡터, 확대 가능)
- PDF (문서용)
```

## 동기화

### 동기화는 언제 사용하나요?

**시나리오 1: 로컬 → 글로벌**
```
프로젝트 전용으로 만든 스킬이 유용해서
다른 프로젝트에서도 사용하고 싶을 때
```

**시나리오 2: 글로벌 → 로컬**
```
글로벌 스킬을 프로젝트에 맞게
커스터마이징하고 싶을 때
```

**시나리오 3: 양방향**
```
로컬에서 개발하고 안정화되면
글로벌로 동기화
```

### 동기화 시 충돌이 발생하면?

**충돌 해결 전략**:
```
1. 덮어쓰기 (Overwrite):
   - 소스로 대상 완전히 교체
   - 주의: 대상 변경사항 손실

2. 병합 (Merge):
   - 양쪽 변경사항 합침
   - 수동 확인 필요

3. 건너뛰기 (Skip):
   - 충돌 파일만 제외
   - 나머지는 동기화

4. 백업 (Backup):
   - 충돌 전 백업 생성
   - 안전하게 시도
```

**권장**:
```
1. 먼저 백업
2. 병합 시도
3. 수동 검토
4. 테스트 후 적용
```

### 자동 동기화는 어떻게 설정하나요?

```
설정 > 동기화 > 자동 동기화
- 활성화
- 간격: 1시간 (권장)
- 방향: 양방향 또는 단방향
- 충돌 처리: 항상 묻기 (권장)
```

**주의**:
- 자동 동기화는 신중히 설정
- 충돌 시 수동 확인 권장
- 백업 자동화 병행

## 성능 및 최적화

### 앱이 느려요

**성능 체크리스트**:
```
1. 프로젝트 크기:
   - 1000개 이상 컴포넌트: 제외 경로 추가
   
2. 스캔 설정:
   - 자동 스캔 간격: 5분 → 10분
   - 제외 경로: node_modules, dist, .git
   
3. 캐시:
   - 설정 > 고급 > 캐시 최적화
   - 주기적으로 캐시 정리
   
4. 메모리:
   - 여러 프로젝트 창 닫기
   - 의존성 그래프 창 닫기 (메모리 많이 사용)
```

### 메모리 사용량이 높아요

**모니터링**:
```
도움말 > 시스템 정보
- 메모리 사용량 확인
```

### 데이터베이스가 커졌어요

**정리 방법**:
```bash
# 1. 백업
cp ~/.vibesmith/db.sqlite ~/.vibesmith/db.sqlite.bak

# 2. 최적화
sqlite3 ~/.vibesmith/db.sqlite "VACUUM;"

# 3. 오래된 데이터 삭제
sqlite3 ~/.vibesmith/db.sqlite "DELETE FROM scan_history WHERE created_at < date('now', '-30 days');"
```
