## 개요

### 통합 컴포넌트 생성 마법사란?

VibeSmith의 **통합 컴포넌트 생성 마법사**는 AI 에이전트 구성요소(Skills, Agents, Commands, Hooks, Rules)를 쉽게 생성할 수 있는 대화형 도구입니다.

### 주요 기능

- ✅ **5가지 타입 통합**: 하나의 마법사로 모든 컴포넌트 생성
- ✅ **템플릿 기반**: 검증된 베스트 프랙티스 템플릿 제공
- ✅ **단계별 가이드**: 6단계 플로우로 쉬운 생성
- ✅ **실시간 미리보기**: 생성 전 내용 확인 및 편집
- ✅ **자동 저장**: 프로젝트에 자동 저장 및 활성화

### 언제 사용하나요?

- 새로운 AI 스킬을 추가하고 싶을 때
- 커스텀 서브에이전트를 만들고 싶을 때
- 자주 사용하는 명령어를 저장하고 싶을 때
- Git 훅을 설정하고 싶을 때
- 프로젝트 규칙을 정의하고 싶을 때

## 5가지 컴포넌트 타입

### 1. 📚 Skill (스킬)

**정의**: AI 에이전트가 특정 작업을 수행하는 방법을 알려주는 지식 문서

**사용 예시**:
- pytest 기반 테스트 자동 생성
- React 컴포넌트 리팩토링
- API 문서 자동 생성
- 코드 리뷰 체크리스트

**파일 형식**: `SKILL.md`

**예시 경로**:
```
.cursor/skills/pytest-write/SKILL.md
.cursor/skills/react-refactor/SKILL.md
```

---

### 2. 🤖 Agent (서브에이전트)

**정의**: 특정 역할을 수행하는 독립적인 AI 에이전트

**사용 예시**:
- 코드 리뷰 전문 에이전트
- 테스트 작성 전문 에이전트
- 문서 작성 전문 에이전트
- 아키텍처 검증 에이전트

**파일 형식**: `AGENT.md`

**예시 경로**:
```
.cursor/agents/code-reviewer.md
.cursor/agents/test-writer.md
```

---

### 3. ⚡ Command (명령어)

**정의**: 자주 사용하는 작업을 명령어로 저장

**사용 예시**:
- 프로젝트 초기화 (`/init-project`)
- 자동 구현 워크플로우 (`/auto-implement`)
- 작업 세션 시작 (`/work-session`)
- 일일 보고서 생성 (`/daily-report`)

**파일 형식**: `.md`

**예시 경로**:
```
.cursor/commands/init-project.md
.cursor/commands/auto-implement.md
```

---

### 4. 🪝 Hook (이벤트 훅)

**정의**: 특정 이벤트 발생 시 자동 실행되는 스크립트

**사용 예시**:
- pre-commit: 커밋 전 린트 검사
- post-merge: 머지 후 의존성 설치
- pre-push: 푸시 전 테스트 실행
- post-checkout: 브랜치 전환 후 환경 설정

**파일 형식**: `.md`

**예시 경로**:
```
.cursor/hooks/pre-commit.md
.cursor/hooks/post-merge.md
```

---

### 5. 📋 Rule (규칙)

**정의**: 프로젝트 전체 또는 특정 파일에 적용되는 코딩 규칙

**사용 예시**:
- 코딩 컨벤션 (네이밍, 포맷)
- 아키텍처 규칙 (레이어 분리)
- 보안 규칙 (API 키 금지)
- 성능 규칙 (번들 크기 제한)

**파일 형식**: `RULE.md`

**예시 경로**:
```
.cursor/rules/CODING_CONVENTION.md
.cursor/rules/packages/web/RULE.md
```

## 마법사 시작하기

### 1. 대시보드에서 시작

1. VibeSmith 대시보드 열기
2. **Quick Actions** 영역에서 **"✨ Component Wizard"** 버튼 클릭

![Component Wizard Button](../assets/wizard-button.png)

### 2. 단축키로 시작 (예정)

- **macOS**: `Cmd + Shift + N`
- **Windows/Linux**: `Ctrl + Shift + N`

## 단계별 사용법

### 1단계: 타입 선택

**목적**: 생성할 컴포넌트 타입을 선택합니다.

**화면 구성**:
- 5개의 타입 카드 (Skill, Agent, Command, Hook, Rule)
- 각 카드에는 아이콘, 이름, 설명 표시

**사용법**:
1. 원하는 타입 카드를 클릭
2. 선택된 카드는 파란색 테두리로 강조
3. **"다음"** 버튼 클릭

**팁**:
- 각 타입의 차이를 모르겠다면 **"가이드 보기"** 링크 클릭
- 잘못 선택했다면 다른 카드를 다시 클릭

![Type Select Step](../assets/wizard-step1.png)

---

### 2단계: 템플릿 선택

**목적**: 선택한 타입에 맞는 템플릿을 선택합니다.

**화면 구성**:
- 타입별 템플릿 카드 목록
- 각 카드에는:
  - 템플릿 이름
  - 설명
  - 난이도 (초급/중급/고급)
  - 예상 시간
  - 태그

**사용법**:
1. 템플릿 카드를 클릭하여 선택
2. **"다음"** 버튼 클릭

**템플릿 예시**:

#### Skill 템플릿
- **pytest 자동 생성**: 테스트 코드 자동 생성 스킬
- **React 컴포넌트 리팩토링**: React 코드 개선 스킬
- **API 문서 생성**: OpenAPI 문서 자동 생성 스킬

#### Agent 템플릿
- **코드 리뷰어**: 코드 품질 검증 에이전트
- **테스트 작성자**: 테스트 코드 생성 에이전트
- **문서 작성자**: 기술 문서 작성 에이전트

#### Command 템플릿
- **프로젝트 초기화**: 새 프로젝트 설정 명령어
- **자동 구현**: 기능 자동 구현 워크플로우
- **일일 보고서**: 작업 로그 자동 생성

#### Hook 템플릿
- **pre-commit**: 커밋 전 검증 훅
- **post-merge**: 머지 후 자동화 훅
- **pre-push**: 푸시 전 테스트 훅

#### Rule 템플릿
- **코딩 컨벤션**: 네이밍, 포맷 규칙
- **아키텍처 규칙**: 레이어 분리 규칙
- **보안 규칙**: 보안 체크리스트

![Template Select Step](../assets/wizard-step2.png)

---

### 3단계: 기본 정보 입력

**목적**: 템플릿에 필요한 기본 정보를 입력합니다.

**화면 구성**:
- 동적 폼 (템플릿마다 다름)
- 필수 필드는 빨간색 별표(*) 표시
- 도움말 텍스트 제공

**공통 필드**:
- **이름** (필수): 컴포넌트 이름
- **설명** (필수): 간단한 설명
- **태그** (선택): 검색용 태그

**템플릿별 추가 필드**:

#### pytest 자동 생성 (Skill)
- **테스트 프레임워크**: pytest, unittest
- **커버리지 목표**: 80%, 90%, 100%
- **픽스처 사용**: 예/아니오

#### 코드 리뷰어 (Agent)
- **리뷰 초점**: 보안, 성능, 가독성
- **심각도 레벨**: Critical, High, Medium, Low
- **자동 수정**: 예/아니오

#### pre-commit (Hook)
- **실행 명령어**: `npm run lint`, `pytest`
- **실패 시 동작**: 중단, 경고
- **타임아웃**: 30초, 60초, 120초

**사용법**:
1. 모든 필수 필드 입력
2. 선택 필드는 필요 시 입력
3. **"다음"** 버튼 클릭

**유효성 검사**:
- 필수 필드 미입력 시 에러 메시지 표시
- 형식 오류 시 도움말 표시

![Basic Info Step](../assets/wizard-step3.png)

---

### 4단계: 미리보기 및 편집

**목적**: 생성된 컴포넌트 내용을 확인하고 필요 시 수정합니다.

**화면 구성**:
- 왼쪽: Markdown 편집기
- 오른쪽: 실시간 미리보기
- 상단: 파일명 표시

**기능**:
- ✅ **실시간 미리보기**: 입력한 내용이 즉시 반영
- ✅ **Markdown 지원**: 제목, 목록, 코드 블록 등
- ✅ **자동 저장**: 편집 내용 자동 저장
- ✅ **되돌리기**: Ctrl+Z / Cmd+Z

**사용법**:
1. 생성된 내용 확인
2. 필요 시 편집기에서 수정
3. 미리보기에서 결과 확인
4. **"다음"** 버튼 클릭

**편집 팁**:
- Markdown 문법을 모르면 **"Markdown 가이드"** 링크 클릭
- 템플릿 구조는 유지하는 것을 권장
- 주석(`<!-- -->`)은 삭제하지 말 것

![Preview Step](../assets/wizard-step4.png)

---

### 5단계: 저장 및 활성화

**목적**: 컴포넌트를 프로젝트에 저장하고 활성화합니다.

**화면 구성**:
- 저장 경로 표시
- 활성화 옵션
- 완료 메시지

**저장 옵션**:
- **프로젝트 선택**: 저장할 프로젝트 선택
- **자동 활성화**: 저장 후 즉시 활성화 (권장)
- **태그 추가**: 검색용 태그 추가

**사용법**:
1. 프로젝트 선택
2. 활성화 옵션 선택 (기본: 활성화)
3. **"저장"** 버튼 클릭
4. 완료 메시지 확인

**저장 후**:
- 대시보드에서 생성된 컴포넌트 확인
- 즉시 사용 가능 (활성화 시)
- Component List에서 관리

## FAQ

### Q1. 마법사를 중간에 닫으면 어떻게 되나요?

**A**: 작업 중인 내용이 있으면 확인 다이얼로그가 표시됩니다.

- **"계속 작업"**: 마법사로 돌아가기
- **"닫기"**: 작업 내용 삭제 및 종료

### Q2. 템플릿을 커스터마이징할 수 있나요?

**A**: 네, 4단계(미리보기)에서 자유롭게 편집할 수 있습니다.

- Markdown 편집기에서 내용 수정
- 실시간 미리보기로 확인
- 템플릿 구조는 유지하는 것을 권장

### Q3. 생성한 컴포넌트를 수정하려면?

**A**: Component List에서 수정할 수 있습니다.

1. 대시보드 → Component List
2. 수정할 컴포넌트 클릭
3. **"Edit"** 버튼 클릭
4. 내용 수정 후 저장

### Q4. 템플릿을 직접 만들 수 있나요?

**A**: 현재는 제공된 템플릿만 사용 가능합니다. 커스텀 템플릿 기능은 Phase 2에서 추가될 예정입니다.

### Q5. 여러 프로젝트에 동시에 저장할 수 있나요?

**A**: 현재는 한 번에 하나의 프로젝트에만 저장 가능합니다. 다른 프로젝트에 복사하려면:

1. Component List에서 컴포넌트 선택
2. **"Copy to Project"** 버튼 클릭
3. 대상 프로젝트 선택

### Q6. 마법사 없이 수동으로 만들 수 있나요?

**A**: 네, 직접 파일을 생성할 수 있습니다.

- `.cursor/skills/` 디렉토리에 `SKILL.md` 생성
- `.cursor/agents/` 디렉토리에 `AGENT.md` 생성
- 등등...

단, 마법사를 사용하면 검증된 템플릿과 자동 저장 기능을 활용할 수 있습니다.

### Q7. 생성한 컴포넌트가 작동하지 않아요

**A**: 다음을 확인하세요:

1. **활성화 여부**: Component List에서 토글이 켜져 있는지 확인
2. **경로 확인**: 올바른 디렉토리에 저장되었는지 확인
3. **문법 오류**: Markdown 문법이 올바른지 확인
4. **재스캔**: Settings → Scan → "Rescan Now" 클릭

### Q8. 템플릿이 마음에 들지 않아요

**A**: 피드백을 보내주세요!

- GitHub Issues: https://github.com/heesubsong/vibesmith-community/issues
- 이메일: support@vibesmith.io

## 트러블슈팅

### 문제 1: "템플릿을 불러올 수 없습니다" 에러

**원인**: 백엔드 API 연결 실패

**해결 방법**:
1. 백엔드 서버가 실행 중인지 확인
   ```bash
   cd packages/api
   make dev
   ```
2. 브라우저 새로고침 (F5)
3. 문제가 지속되면 로그 확인
   ```bash
   tail -f packages/api/logs/app.log
   ```

---

### 문제 2: "저장할 수 없습니다" 에러

**원인**: 파일 시스템 권한 또는 경로 오류

**해결 방법**:
1. 프로젝트 경로가 올바른지 확인
   - Settings → Projects → 경로 확인
2. 파일 시스템 권한 확인
   ```bash
   ls -la .cursor/
   ```
3. 디렉토리가 없으면 생성
   ```bash
   mkdir -p .cursor/skills .cursor/agents .cursor/commands .cursor/hooks .cursor/rules
   ```

---

### 문제 3: 마법사가 느려요

**원인**: 대량의 템플릿 또는 네트워크 지연

**해결 방법**:
1. 브라우저 캐시 삭제
2. 백엔드 로그 확인 (느린 쿼리)
3. 템플릿 개수 확인
   ```bash
   curl http://localhost:8000/api/templates | jq 'length'
   ```

---

### 문제 4: 미리보기가 깨져요

**원인**: Markdown 문법 오류

**해결 방법**:
1. 편집기에서 문법 오류 확인
2. 특수 문자 이스케이프 (`\*`, `\[`, `\]`)
3. 코드 블록 닫기 확인 (` ``` `)

---

### 문제 5: 생성한 컴포넌트가 목록에 안 보여요

**원인**: 스캔이 필요함

**해결 방법**:
1. Settings → Scan → "Rescan Now" 클릭
2. 몇 초 기다린 후 대시보드로 돌아가기
3. Component List 새로고침
